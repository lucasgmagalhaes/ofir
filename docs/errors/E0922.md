# E0922: an index's history was rewritten

`ofir.lock` pins the commit of each registry index the resolution read
(ADR 0081). When the index is fetched again, its new head must descend
from that commit; here it does not, so commits were removed from the
index's history. Packages already published may have changed, so the
resolution stops instead of reading the new history.

## Example

```text
error[E0922]: the history of the registry `https://github.com/acme/index` was rewritten
  = note: `ofir.lock` has the commit `3f2a...` of the registry
  = note: its head `9c41...` does not descend from it
  = note: `ofir update --index-reset` accepts the new history
```

## Fix

Ask the registry's maintainers why its history changed. Once the new
history is known to be right, accept it and record its head in the
lock:

```text
ofir update --index-reset
```
