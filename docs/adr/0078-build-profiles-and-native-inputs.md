# 0078. Build profiles and native inputs

- Status: Accepted
- Date: 2026-11-18

## Context

OFIR-66 asks for build profiles, configuration and native or generated
inputs, and, if build hooks are adopted, for their host and target, their
declared inputs and their network and permission policy. A build has two
modes today: the default (`-O0`, one LLVM module per Ofir module,
`@cfg(debug)`) and `--release` (`-O2`, one module). C code reaches a
program only as a library named by `@link` (ADR 0062), built by hand.

Cargo has `[profile.*]` with `inherits`, and `build.rs`, which runs any
code at build time; Zig has `build.zig`; Go has none and keeps
`go generate` outside the build.

## Decision

**Profiles.** `--profile=NAME` chooses a profile; `--release` is
`--profile=release`, and the two cannot both be given. `dev` (the default)
and `release` are built in. The manifest's `"profiles"` names others and
changes the built-in ones:

```jsonc
"profiles": {
  "release": {"debugInfo": true},
  "fast": {"inherits": "release", "opt": 3},
  "check": {"opt": 1}
}
```

- `inherits`: `"dev"` (the default) or `"release"`. A profile that
  inherits `release` is built as one LLVM module, with release code
  generation and `@cfg(debug)` false; one that inherits `dev` is not. The
  built-in profiles have no `inherits`.
- `opt`: the optimization level, 0 to 3 (`dev` 0, `release` 2).
- `debugInfo`: whether debug info is written, as with `-g` (both false).

Only the root's `profiles` are read: the workspace root's in a workspace
(ADR 0077). A profile that does not exist, an unknown key or a bad value
is E0918. Arithmetic is checked in every profile (ADR 0005).

**Configuration.** `@cfg` conditions stay `os`, `arch`, `debug` and
`test` (spec 12.4). There are no user `--cfg` flags or features: a
program that needs a variant uses a profile and `@cfg(debug)`, or a
dependency.

**Native inputs.** A package's `"build": {"native": ["c/fast.c"]}` lists
C files, relative to its manifest. Every package's native files are
compiled by the same clang, with the profile's optimization level and the
target (`--target`), and linked into the program; their functions are
declared in an `extern "C"` block. A missing file is E0918.

**No build hooks.** Ofir does not run code from a package at build time.
A build reads the declared sources, native files and manifests, and runs
only the compiler and clang, so it needs no network or permission policy.
Generated code is either computed at compile time (`comptime`, spec 15) or
generated by a separate step and committed.

## Consequences

- A team can name the builds it uses (`fast`, `profiling`) once, in the
  manifest.
- A package can ship a small C part without a build system, and that part
  is cross compiled with the program.
- Without hooks, a package cannot probe the machine or build a large C
  library with its own build system: it links a library installed apart
  with `@link`.
- A build's inputs are known before it starts: the object cache and
  reproducible builds (OFIR-70) need no sandbox.
