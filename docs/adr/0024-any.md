# 0024. `Any`: values of any type through `dyn Any`

- Status: Accepted; the spelling `dyn Any` is superseded by [0039](0039-any-type.md)
- Date: 2026-11-02

## Context

Ofir has no type that holds a value of any type. Generics (spec 8) cover
code that works for every type known at compile time, union types (spec
17) a closed set of types, and `dyn Interface` (spec 9.7) an open set of
types that share methods. Some programs still need a value whose type is
not known in advance and shares nothing: a heterogeneous container (a
registry of plugins' state, an event payload, the extensions map of a
request), a value passed through a library that does not know its type
and handed back to the code that does.

Three designs were considered:

1. **A built-in `any` type**, as in TypeScript or Go's `interface{}`. It
   is a type the compiler special-cases everywhere (assignability, method
   calls, equality), and it invites implicit conversions back, which Ofir
   does not have (spec 2.2).
2. **Reflection** on any value. It needs type metadata for every type in
   every binary, and code that inspects fields at run time loses the
   checks the compiler would make.
3. **An interface in std**, as Rust's `std::any::Any`: `dyn Any` is an
   ordinary `dyn` value, and getting the value back is an ordinary type
   switch (spec 9.8).

## Decision

`std.core` declares, in the prelude, the interface

```ofir
pub interface Any {
    fn typeName(self) str
}
```

- **Every type satisfies `Any`**, except the types that hold references
  (`&T`, a `ref struct`, a type with such a field), which cannot be stored
  (spec 5.6, E0702). The compiler provides `typeName` for every type, as
  it derives the built-in interfaces (spec 9.9); a type cannot declare its
  own. It returns the type's name as written in messages: `"int"`,
  `"List<str>"`, `"app.Config"`.
- A value becomes a `dyn Any` like any `dyn` value: implicitly where the
  expected type is `dyn Any`, `Box<dyn Any>` or `&dyn Any` (spec 9.7).
- The value is recovered with a type switch (spec 9.8); the `match`
  needs a `_` arm, since the set of types is open (E0500):

```ofir
fn describe(v: dyn Any) str {
    return match v {
        n: int => "the int {n}"
        s: str => "the str {s}"
        p: Point => "a point at {p.x}, {p.y}"
        _ => "a {v.typeName()}"
    }
}

let things: List<Box<dyn Any>> = [Box.new(1), Box.new("two"), Box.new(Point{x: 3, y: 4})]
for thing in things {
    println(describe(*thing))
}
```

- A type test binds like any pattern (spec 5.5): on a borrowed `dyn Any`
  the binding borrows the value; on an owned `Box<dyn Any>`, the binding
  takes the value by move and the box is freed:

```ofir
fn takeConfig(value: move Box<dyn Any>) Option<Config> {
    return match value {
        c: Config => .Some(c)   // moved out of the box
        _ => .None              // the box is dropped with its value
    }
}
```

- `if let c: Config = value { ... }` tests a single type.
- A type test that names a type that does not satisfy the interface of
  the `dyn` value can never match (E0354), as `n: &int` on a `dyn Any`.

There is no `any` keyword, no `is` operator, no conversion with `as`
from `dyn Any` and no reflection: the only way to the concrete value is a
type test, which the compiler checks.

## Consequences

- `Any` adds no rule to the language: `dyn`, vtables, type ids and type
  switches are already specified (spec 9.7, 9.8); `Any` is an interface
  every type satisfies, and `typeName` a method every type has.
- Each type used as a `dyn Any` gets a vtable with its type id, size,
  alignment, drop function and `typeName`; types never converted pay
  nothing.
- A function taking `dyn Any` accepts anything, so it is checked less
  than a generic one or one taking a union; the style guide recommends
  generics, unions or a dedicated interface first, and `dyn Any` only for
  values that pass through code that cannot know their type
  (docs/style-guide.md).
- Two `dyn Any` values are not comparable or hashable, since `Any` does
  not include `Eq` or `Hash`; code that needs them uses an interface that
  does.
- It ships with `dyn` (roadmap 5.4).
